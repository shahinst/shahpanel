## 📌 Что такое shahpanel?

Веб-панель для **продажи VPN-сервиса и управления им** с многоуровневой структурой. У каждого уровня свой кошелёк, своё ценообразование, свои клиенты и свои отчёты:

```
Администратор ─┬─ Агент ─┬─ Продавец ─┬─ Клиент
               │         │            └─ Клиент
               │         └─ Продавец ─── Клиент
               └─ Агент ─── Продавец ─── Клиент
```

Панель общается с вашими серверами напрямую и тут же **создаёт, продлевает, ограничивает и закрывает** аккаунты:

| Сервер | Поддерживаемые сервисы |
|:--|:--|
| 🖧 **MikroTik RouterOS** | PPPoE / PPP · WireGuard · OpenVPN · L2TP |
| 🌐 **Sanaei (3x-ui)** | VMess · VLESS · Trojan |
| 🛡 **Pasarguard** | Все inbound |
| 🌊 **Remnawave** | Internal Squads — совместимо с API версии 3.x |
| 🔒 **Cisco AnyConnect (ASA)** | Пользователи VPN через REST API устройства |
| 🔓 **OpenConnect / ocserv** | Пользователи VPN через управляющий JSON API |

## 🚀 Установка

> **Установка выполняется только по SSH.** Веб-установщика нет — никакой адрес в самой панели установку не запускает.

### Шаг 0 — что понадобится

| Пункт | Описание |
|:--|:--|
| **Сервер** | Ubuntu 22.04 или 24.04 (чистый и пустой, минимум 1 ГБ ОЗУ) |
| **Доступ** | Пользователь `root` или `sudo` |
| **Домен** | **Необязательно.** В обоих случаях выдаётся действительный сертификат — с доменом от Let's Encrypt, без домена напрямую для самого IP. |

Ставить PHP, MySQL, Nginx или Composer вручную **не нужно** — скрипт устанавливает всё сам.

<details>
<summary><b>Как настроить A-запись?</b></summary>

<br>

В панели управления вашим доменом создайте запись:

| Type | Name | Content |
|:--|:--|:--|
| `A` | `panel` | IP вашего сервера |

Если вы используете Cloudflare, на время выпуска сертификата **временно сделайте оранжевое облако (Proxy) серым**.

Убедитесь этой командой, что DNS распространился:

```bash
dig +short panel.example.com
```

Она должна вернуть ровно IP вашего сервера. Распространение DNS иногда занимает до нескольких часов.

</details>

### Шаг 1 — подключение к серверу

```bash
ssh root@YOUR_SERVER_IP
```

### Шаг 2 — запуск установки

```bash
curl -fsSLO https://raw.githubusercontent.com/shahinst/shahpanel/master/install.sh
sudo bash install.sh
```

Скрипт поздоровается и **задаст один вопрос: есть ли у вас домен?**

- **Домен есть** → введите домен. Установщик проверит, что запись `A` действительно указывает на этот сервер, и, если всё верно, получит бесплатный сертификат **Let's Encrypt**. Браузер не покажет никаких предупреждений.
- **Домена нет** → нажмите Enter. Установщик получит действительный сертификат Let's Encrypt **для самого IP сервера**, и браузер не покажет никаких предупреждений. Такие сертификаты короткоживущие (около 6 дней), и `acme.sh` автоматически продлевает их четыре раза в сутки. Если выпуск по какой-то причине не удастся, панель поднимется с self-signed сертификатом, а на экран будет выведена команда для повторной попытки.

Если домен известен заранее или установка должна пройти без вопросов:

```bash
sudo bash install.sh panel.example.com     # сразу с доменом
sudo bash install.sh --ip --yes            # сразу на IP, без единого вопроса
```

Дополнительные параметры:

| Параметр | Что делает |
|:--|:--|
| `--ip` | Без домена; установка на IP сервера с действительным сертификатом для этого же IP |
| `--yes` | Не задавать вопросов и брать значения по умолчанию |
| `--with-phpmyadmin` | Установить phpMyAdmin по случайному пути |
| `--with-security` | Установить защитный щит (CrowdSec + fail2ban + ClamAV) |
| `--no-ssl` | Без TLS (только HTTP) — не рекомендуется |

### Шаг 3 — подождите

Установка занимает **от 10 до 45 минут** в зависимости от сервера — на двухъядерной машине один только этап миграций базы данных длится около 15 минут. Если процесс несколько минут стоит на одном шаге, это не зависание. Скрипт последовательно выполняет 13 шагов:

```
[1/13]  Проверка сервера и выбор домена или IP
[2/13]  Установка PHP 8.3 · MySQL · Nginx · ipset   (+ certbot в режиме домена)
[3/13]  Установка Composer
[4/13]  Загрузка кода панели
[5/13]  Установка PHP-зависимостей (composer install)
[6/13]  Создание базы данных и её пользователя
[7/13]  Настройка .env и ключа шифрования
[8/13]  Права на файлы и создание таблиц базы данных
[9/13]  Установка помощника брандмауэра и загрузка диапазонов стран
[10/13] Настройка Nginx        (+ временный self-signed сертификат в режиме IP)
[11/13] Включение TLS
[12/13] Установка cron-планировщика (+ phpMyAdmin и защитный щит, если выбраны)
[13/13] Создание пользователя-администратора
```

### Шаг 4 — запишите данные для входа

В конце **адрес входа администратора**, пароль администратора и пароль базы данных выводятся **только на экран** — в файл журнала они намеренно не попадают. **Запишите их сразу же.**

Одна копия сохраняется здесь (прочитать может только `root`):

```bash
sudo cat /var/www/shahpanel/storage/app/INSTALL_CREDENTIALS.txt
```

Вывод выглядит примерно так:

```
Panel URL : https://panel.example.com/p7f3a9c2e51
Username  : admin
Password  : ••••••••••••

Database  : shahpanel
DB user   : shahpanel@127.0.0.1
DB pass   : ••••••••••••
```

Полный журнал установки (без единого пароля) находится в `/var/log/shahpanel-install.log`.

### Шаг 5 — вход

Входите по **тому самому случайному адресу**, который был напечатан на предыдущем шаге, а не по `/admin`:

```
https://panel.example.com/p7f3a9c2e51     ← установка с доменом
https://203.0.113.45/p7f3a9c2e51          ← установка на IP
```

В обоих случаях (домен или IP) сертификат действительный, и браузер не выдаёт предупреждений.

> ⚠️ **Путь входа администратора случайный, а не `/admin`.** Первое, что пробует любой автоматический сканер, — это `/admin`, поэтому он намеренно не используется. Если вы потеряете этот адрес, прочитайте его заново из файла выше.

> ⚠️ **Первое, что нужно сделать: сменить пароль администратора.**
> После этого рекомендуется включить двухфакторный вход в разделе профиля.

<details>
<summary><b>Изменение путей входа в панели</b></summary>

<br>

Из панели администратора: **Настройки → Безопасность → Пути панелей**. Там можно изменить все три пути:

| Панель | По умолчанию | Описание |
|:--|:--|:--|
| Администратор | Случайный, задаётся при установке | Виден только вам |
| Агент | `agent` | Администратор может изменить |
| Продавец | `seller` | Администратор может изменить |

Доступ к этой странице есть только у администратора; агент и продавец не могут изменить свой путь.

Путь должен состоять минимум из 3 символов и содержать только `a-z`, `0-9`, `-` и `_`. Несколько слов зарезервированы (`api`, `client`, `install`, `login`, `portal`, `up` и др.) и не принимаются.

Параметр «Блокировать старые пути по умолчанию» приводит к тому, что старые адреса (`/admin`, `/agent`, `/seller`) перестают отвечать.

</details>

<details>
<summary><b>phpMyAdmin</b></summary>

<br>

Устанавливается только с ключом `--with-phpmyadmin` и размещается по случайному пути (не `/phpmyadmin`). Вход выполняется **тем же пользователем и паролем базы данных панели**; у этого пользователя есть доступ только к базе самой панели, а не ко всему MySQL.

⚠️ phpMyAdmin — одно из самых атакуемых веб-приложений. Рекомендуется не устанавливать его без реальной необходимости. Чтобы удалить его позже:

```bash
apt-get remove --purge phpmyadmin
rm -f /etc/nginx/snippets/shahpanel-phpmyadmin.conf
systemctl reload nginx
```

</details>

### Шаг 6 — первичная настройка панели

После входа по порядку:

1. **Серверы** → добавьте свой сервер MikroTik / 3x-ui / Pasarguard / Remnawave / Cisco и нажмите «Проверить подключение».
2. **Пакеты** → задайте пакеты для продажи (трафик, срок, цена).
3. **Агенты** → при необходимости создайте агента и задайте лимит его кредита.
4. **Настройки → Платёжные шлюзы** → включите нужный шлюз и введите его ключи.

<details>
<summary><b>Пользовательские параметры установки</b></summary>

<br>

Меняются через переменные окружения:

```bash
sudo APP_DIR=/var/www/panel DB_NAME=mypanel ADMIN_USER=root \
     EMAIL=me@example.com bash install.sh panel.example.com
```

| Переменная | По умолчанию | Описание |
|:--|:--|:--|
| `APP_DIR` | `/var/www/shahpanel` | Каталог установки |
| `REPO` | Официальный репозиторий | Адрес git-репозитория |
| `BRANCH` | `master` | Ветка |
| `DB_NAME` | `shahpanel` | Имя базы данных |
| `DB_USER` | `shahpanel` | Пользователь базы данных |
| `ADMIN_USER` | `admin` | Имя пользователя администратора |
| `EMAIL` | Нет | Email для Let's Encrypt и администратора |

Если репозиторий приватный, задайте также `GITHUB_TOKEN`. После клонирования токен удаляется из `.git/config`, а в журнале маскируется.

</details>

<details>
<summary><b>Если сертификат SSL получить не удалось</b></summary>

<br>

Обычно это значит, что DNS ещё не распространился. После того как DNS заработает:

```bash
certbot --nginx -d panel.example.com --redirect
```

Затем выставьте в `.env` это значение в `true`, чтобы cookie сессии передавалась только по HTTPS:

```env
SESSION_SECURE_COOKIE=true
```

И очистите кеш:

```bash
cd /var/www/shahpanel && sudo -u www-data php artisan optimize:clear
```

</details>

<details>
<summary><b>Ручная установка (когда сервер уже подготовлен)</b></summary>

<br>

Если вы сами управляете PHP, MySQL и веб-сервером и не хотите использовать `install.sh`.

**Требования:** PHP 8.2+ с расширениями `mbstring`, `xml`, `curl`, `zip`, `bcmath`, `mysql`, `gd`, `openssl`, `dom` · MySQL 8 или MariaDB · Composer.
Node/npm не нужны — собранные файлы (`public/build`) лежат в репозитории.

```bash
git clone https://github.com/shahinst/shahpanel.git /var/www/shahpanel
cd /var/www/shahpanel

composer install --no-dev --optimize-autoloader

cp .env.example .env
php artisan key:generate
```

Затем отредактируйте `.env`:

```env
APP_URL=https://your-domain.com
APP_ENV=production
APP_DEBUG=false

DB_DATABASE=your_db
DB_USERNAME=your_db_user
DB_PASSWORD=your_db_password
SESSION_SECURE_COOKIE=true

# Путь входа администратора — задайте случайную строку, а не admin
VPN_ADMIN_PATH=p7f3a9c2e51
```

```bash
php artisan migrate --force
php artisan storage:link

# Права доступа
chown -R www-data:www-data storage bootstrap/cache
chmod -R 775 storage bootstrap/cache

# .env содержит APP_KEY и не должен быть доступен на чтение другим пользователям сервера
chown root:www-data .env && chmod 640 .env

# Создание администратора и снятие блокировки установки
php artisan install:finalize \
  --admin-username=admin \
  --admin-email=admin@example.com \
  --admin-password='<пароль>' \
  --admin-name=Administrator

echo "installed $(date -Is)" > .installed.lock
chown www-data:www-data .installed.lock
```

> 🔒 Вместо `--admin-password` можно задать переменную окружения `VPN_ADMIN_PASSWORD`, чтобы пароль не был виден в выводе `ps`. `install.sh` делает именно так.

Укажите document root на `public/` и добавьте cron-планировщик из раздела [Обслуживание](#-обслуживание). Пока файл `.installed.lock` не создан, панель на любой запрос отдаёт страницу «ещё не установлено».

</details>

## 🔌 API для реселлеров (подключение Telegram-бота)

Агент и продавец могут подключить панель к своему Telegram-боту и продавать аккаунты,
продлевать их, получать конфигурацию клиента и видеть свой кошелёк и своих подчинённых.

**Создание токена:** вход в панель → меню **Настройки** → **API и бот** → создать токен.
Там же есть страница **Справка по API**, где показаны параметры каждой конечной точки.

Либо прямо через сам API:

```bash
curl -X POST https://YOUR-PANEL/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"reseller1","password":"...","device_name":"my-bot"}'
```

Затем передавайте токен в каждом запросе:

```bash
curl https://YOUR-PANEL/api/v1/accounts \
  -H 'Authorization: Bearer mp_xxxxxxxx'
```

У каждого ответа один и тот же формат, поэтому боту достаточно проверять `ok`:

```json
{ "ok": true,  "data": { }, "meta": { "pagination": { } } }
{ "ok": false, "error": { "code": "...", "message": "..." } }
```

**Важные замечания**

- Токен получают только роли Агент и Продавец; администратор и клиент — нет.
- Продавец видит только свои аккаунты, агент — всю свою структуру: правила те же, что и в самой панели.
- Каждый токен можно ограничить набором конкретных прав и привязать к IP.
- Пополнение кошелька через API невозможно; в самой панели такое право есть только у администратора.
- Лимит по умолчанию — 120 запросов в минуту на токен (настраивается в диапазоне от 10 до 600).

Полная документация: [`docs/API.md`](docs/API.md) — готовые примеры на PHP и Python: [`docs/bot-client/`](docs/bot-client/)
Для Cisco AnyConnect: [`docs/CISCO_ANYCONNECT_API.md`](docs/CISCO_ANYCONNECT_API.md)
Для OpenConnect / ocserv: [`docs/OCSERV_API.md`](docs/OCSERV_API.md)

## 🤖 Подключение готовых ботов (Mirza и WizWiz)

Писать своего бота не обязательно — готовые боты подключаются к shahpanel без изменений.

| Бот | Статус |
|:--|:--|
| **Mirza** (MirzaBot) | ✅ Поддерживается |
| **WizWiz** | ✅ Поддерживается |

### Как подключить

В панели самого бота добавьте сервер типа **Marzban** и укажите:

| Поле | Значение |
|:--|:--|
| Адрес панели | `https://YOUR-PANEL` |
| Имя пользователя | имя пользователя аккаунта **Агента** или **Продавца** |
| Пароль | пароль этого аккаунта |

Это всё. Укажите тип панели Marzban — остальное бот сделает сам.

### Что важно знать

**Не подключайтесь аккаунтом администратора.** Принимаются только Агенты и Продавцы. Каждая продажа бота списывается с кошелька этого аккаунта и попадает в бухгалтерию панели; кошелёк администратора не ограничен, поэтому такие продажи не отражались бы в отчётах.

**Ваши пакеты видны как inbounds.** При создании плана в боте вы видите пакеты, назначенные этому Агенту — по одной записи на пакет и срок. Выберите нужную; больше ничего настраивать не требуется.

**Объём и срок:** для фиксированного пакета применяются его собственные объём и срок, а введённые в боте значения игнорируются. Для эластичного пакета (цена за ГБ) используются значения бота.

**Что можно продавать:** Sanaei (3x-ui), Pasarguard и Remnawave. MikroTik, Cisco AnyConnect и OpenConnect так продавать нельзя — это сервисы с логином и паролем без ссылки подписки, и это ограничение самого протокола.

**Аккаунт с включённой двухфакторной аутентификацией не может подключить бота**, так как в протоколе нет поля для второго фактора. Создайте для бота отдельный аккаунт Агента.

**Если бот сообщил «создано», а аккаунта нет**, посмотрите журнал панели:

```bash
sudo grep -i marzban /var/www/shahpanel/storage/logs/laravel-*.log | tail -20
```

Некоторые боты принимают ответ с ошибкой за успех. Настоящая причина всегда есть в журнале панели.

## 🛡 Брандмауэр входа

Не даёт подбирать пароль и может закрыть доступ целым диапазонам одной страны.

**Как это работает**

1. Несколько неверных паролей подряд с одного IP ⇒ этот адрес на некоторое время теряет доступ к странице входа.
2. Если после блокировки он продолжает ломиться, адрес передаётся в `ipset`, и дальше им занимается ядро.
3. Успешный вход стирает предыдущие ошибки того же адреса.

Закрываются только **пути входа**, а не весь сайт: в сетях, где за одним IP сидят десятки
абонентов (CGNAT), полная блокировка сайта отрезала бы и ни в чём не виноватых клиентов. Портал
клиента и ссылка подписки остаются доступны всегда.

**Управление из панели:** администратор → **Настройки** → **Брандмауэр входа** — список заблокированных
адресов с флагом страны, разблокировка в один клик, ручная блокировка и белый список.

**Управление из командной строки**

```bash
php artisan firewall status            # состояние цепочки и число блокировок
php artisan firewall block 1.2.3.4     # ручная блокировка (--minutes=0 — навсегда)
php artisan firewall unblock 1.2.3.4   # разблокировать один адрес
php artisan firewall flush             # снять все блокировки
```

**Блокировка целой страны** — загружаются диапазоны Китая, обновление каждый понедельник в 03:30:

```bash
php artisan firewall:sync-country-data   # скачать и перезагрузить
php artisan firewall cn-clear            # снять блокировку страны
```

**Устройство.** Работу на уровне ядра выполняет root-помощник, который установщик кладёт в
`/usr/local/sbin/panel-firewall`, и в sudoers для `www-data` разрешён только этот один файл. То есть
веб-пользователь может запросить блокировку, но **не может переписать список, по которому его
самого фильтруют**. Данные по странам хранятся в
`/var/lib/panel-firewall`.

> Помощник трогает только цепочку `INPUT`; `OUTPUT` и `FORWARD` — никогда. Блокировку
> loopback, приватных диапазонов и собственного IP сервера он тоже отклоняет, так что одно
> неверное правило не может отрезать сервер от сети. Добавьте свой адрес в белый список, чтобы
> ошибка в пароле не закрыла вам доступ.

## 🔄 Обновление

```bash
cd /var/www/shahpanel
sudo bash update.sh
```

Скрипт по порядку:

1. **Сначала делает бэкап базы данных** (в `/var/backups/shahpanel/`, хранятся последние 10 копий)
2. Забирает новый код
3. Выполняет `composer install` и `migrate`
4. Очищает кеш и перезапускает worker очереди

Если бэкап не удался, скрипт **не трогает код**. Если вы вручную изменили какой-то файл на сервере, он **останавливается** и ничего не перезаписывает.

## 🔧 Обслуживание

### Cron (планировщик)

Без него очередь не обрабатывается, а аккаунты не истекают вовремя. `install.sh` устанавливает его сам:

```
* * * * * www-data cd /var/www/shahpanel && php artisan schedule:run >> /dev/null 2>&1
```

Этой одной строки достаточно — **отдельная служба для очереди не нужна**, потому что планировщик каждую минуту сам запускает
`queue:work --stop-when-empty`.

Проверить его работоспособность из панели: **Настройки → Автоматизация → Задания cron**

### Что выполняется автоматически

| Задача | Периодичность |
|:--|:--|
| Синхронизация трафика аккаунтов (`sync:usage`) | каждые 5 минут |
| Проверка срока и отключение аккаунтов (`accounts:check-expiry`) | каждые 10 минут |
| Обработка очереди (`queue:work`) | каждую минуту |
| Сбор метрик роутеров и обнаружение drift | каждые 1–5 минут |
| Очистка истёкших блокировок брандмауэра | каждые 15 минут |
| Отправка оповещений (`alerts:dispatch`) | ежечасно |
| Бэкап базы данных (`backup:database`) | каждую ночь в 02:00 |
| Ежедневный отчёт (`reports:daily-rollup`) | каждую ночь в 00:00 |
| Автозакрытие тикетов | ежедневно |
| Очистка метрик туннелей | каждую ночь в 03:30 |
| Обновление диапазонов стран | по понедельникам в 03:30 |

> ⚠️ Ночной бэкап каждую ночь добавляет один файл в `storage`. Время от времени проверяйте
> место на диске и удаляйте старые файлы.

### Бэкап и перенос на новый сервер

```bash
# Сделать бэкап и отправить на другой сервер
bash scripts/db-migrate.sh backup --send root@newhost:/root/

# Восстановление на новом сервере
bash scripts/db-migrate.sh restore --latest
```

> 🔑 Обязательно перенесите и файл `.env`. Без **прежнего** `APP_KEY` сохранённые имена пользователей и пароли роутеров расшифровать невозможно.

### Кеш маршрутов (необязательно, для скорости)

```bash
cd /var/www/shahpanel
sudo -u www-data php artisan route:cache
```

Путь входа каждой панели можно менять, и он читается из базы данных, поэтому в кеше он замораживается. Панель справляется с этим сама: при каждом изменении пути в разделе безопасности кеш пересобирается.

## 🆘 Устранение неполадок

### Панель не открывается

Есть диагностическая страница, работающая без Laravel: она показывает состояние базы данных, права на файлы и последние ошибки, а также может очистить кеш или выполнить миграции.

Поскольку она делает опасные вещи, **по умолчанию она закрыта** и всем отдаёт 404. Чтобы открыть её, задайте токен в `.env`:

```bash
cd /var/www/shahpanel
echo "MAINTAIN_TOKEN=$(php -r 'echo bin2hex(random_bytes(16));')" >> .env
```

Затем откройте: `https://panel.example.com/maintain.php?key=<токен>`

> После решения проблемы обязательно очистите `MAINTAIN_TOKEN`, чтобы страница снова закрылась. Пока это значение пустое, тот адрес отдаёт 404 всем.

### Частые проблемы

<details>
<summary><b>После перезагрузки сервера панель отдаёт 502</b></summary>

<br>

Обычно не поднялись MySQL или PHP-FPM:

```bash
systemctl start mysql php8.3-fpm nginx
systemctl enable mysql php8.3-fpm nginx   # чтобы в следующий раз поднимались сами
```

</details>

<details>
<summary><b>Аккаунты не истекают / трафик не обновляется</b></summary>

<br>

Cron не работает. Проверьте:

```bash
systemctl status cron
cat /etc/cron.d/shahpanel-scheduler
cd /var/www/shahpanel && sudo -u www-data php artisan schedule:run
```

</details>

<details>
<summary><b>Белая страница или ошибка 500</b></summary>

<br>

```bash
tail -50 /var/www/shahpanel/storage/logs/laravel.log
cd /var/www/shahpanel && sudo -u www-data php artisan optimize:clear
chown -R www-data:www-data storage bootstrap/cache
chmod -R 775 storage bootstrap/cache
```

</details>

<details>
<summary><b>Я изменил путь входа в панель и теперь не могу войти</b></summary>

<br>

Прочитайте текущий путь из базы данных:

```bash
cd /var/www/shahpanel
sudo -u www-data php artisan tinker --execute="echo App\Models\Setting::getValue('portal_path_admin');"
```

Чтобы вернуть значение по умолчанию:

```bash
sudo -u www-data php artisan tinker --execute="App\Models\Setting::setValue('portal_path_admin','admin');"
sudo -u www-data php artisan optimize:clear
```

> `tinker` — зависимость для разработки. Если вы устанавливали через `composer install --no-dev`, прочитайте значение `VPN_ADMIN_PATH` из `.env`.

</details>

<details>
<summary><b>Не удаётся подключиться к серверу MikroTik</b></summary>

<br>

- Служба API на роутере должна быть включена: `/ip service enable api`
- Порт (по умолчанию `8728`, с SSL — `8729`) должен быть открыт со стороны сервера панели
- У пользователя RouterOS должно быть право `api`
- Если у вас есть файрвол, разрешите IP сервера панели

</details>

<details>
<summary><b>Ошибка сертификата SSL при подключении к панели 3x-ui или Remnawave</b></summary>

<br>

Панель по умолчанию **проверяет** TLS-сертификат удалённых серверов, потому что имя пользователя
и пароль администратора той панели передаются в каждом запросе.

Если у целевой панели self-signed сертификат, снимите на странице редактирования этого сервера
галочку «Проверять SSL-сертификат панели». Эта настройка задаётся отдельно для каждого сервера.

</details>

## ❓ Частые вопросы

<details>
<summary><b>Устанавливается ли на шаред-хостинг (cPanel / DirectAdmin)?</b></summary>

<br>

Не поддерживается. Панели нужны поминутный cron, фоновая очередь и прямое подключение к API роутеров. Достаточно недорогого VPS.

</details>

<details>
<summary><b>Сколько серверов можно добавить?</b></summary>

<br>

Ограничений нет. У каждого сервера свой собственный лимит аккаунтов, который задаётся на странице сервера.

</details>

<details>
<summary><b>Можно ли использовать MikroTik и Remnawave одновременно?</b></summary>

<br>

Да. Каждый пакет привязан к одному типу сервиса, и панель сама создаёт аккаунт на нужном сервере.

</details>

<details>
<summary><b>Что будет, если я поменяю APP_KEY?</b></summary>

<br>

Сохранённые имена пользователей и пароли всех роутеров и панелей станут **невосстановимыми**. Никогда его не меняйте и делайте бэкап `.env`.

</details>

<details>
<summary><b>Какие данные панель отправляет наружу?</b></summary>

<br>

Никакие. Единственные внешние соединения — это ваши собственные серверы, включённые вами платёжные шлюзы и загрузка диапазонов стран для брандмауэра. QR-код двухфакторного входа тоже генерируется на этом же сервере.

</details>
